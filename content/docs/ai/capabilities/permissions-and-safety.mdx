---
title: Permissions and Safety
description: Apply company scope, permissions, redaction, and confirmation rules to Fleetbase AI capabilities.
---

Fleetbase AI capabilities must respect normal Fleetbase boundaries.

<Callout type="warn">
Capabilities are production data access points. Treat them like API endpoints: scoped, permission checked, validated, and auditable.
</Callout>

## Required checks

Capabilities should enforce:

- company scope
- user permissions
- resource ownership
- safe output fields
- result limits
- action confirmation

## Recommended guardrails

| Guardrail | Why it matters |
| :--- | :--- |
| **Company scope** | Prevents cross-organization data leakage |
| **Permission checks** | Keeps AI access aligned with normal Fleetbase UI/API access |
| **Result caps** | Prevents huge payloads from being sent to providers |
| **Sanitized samples** | Gives useful grounding without exposing full records |
| **Preview confirmation** | Prevents silent mutations from natural-language prompts |
| **Task steps** | Makes data access and action execution auditable |

## Provider boundaries

Providers should receive only the context needed to answer the prompt or render the preview. They should not receive unrestricted model payloads or secrets.

## Action boundaries

Actions should not mutate data until the user explicitly confirms the preview. Apply methods should use the same validation path the module uses outside AI.

## Redaction

Admin views should redact raw prompt and response content by default. Reveal actions require permission and should be logged.
